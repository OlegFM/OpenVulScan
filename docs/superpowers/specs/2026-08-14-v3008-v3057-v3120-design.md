# V3008 / V3057 / V3120 — design (ovs-2qi.16)

**Bead:** ovs-2qi.16. **Date:** 2026-08-14. **Status:** Accepted.

The bead groups the three as "dead store", but the actual PVS semantics differ; each rule
gets its own mechanism, all definite-only (anti-FP v1):

## V3008 — variable assigned twice successively (dead store)

- PVS: "The 'x' variable is assigned values twice successively. Perhaps this is a mistake."
- Mechanism: `AstRule` over the method's CFG (the V3151 precedent) — **intra-basic-block**
  statement scan. Within one lowered block, statement order is total and branches split
  blocks, so "successively" ≡ same block with no intervening read.
- Per block: walk `block.Operations`; for a simple assignment (or declarator) to a local
  `x`: first clear pending entries for every local READ inside the statement's value, then
  if `pending[x]` exists report **at the second assignment**, then `pending[x] = this`.
  Any other statement clears pending for all locals it references (reads, ref/out args,
  compound/increment targets). Pending dies at block end.
- `x = 1; x = x + 1` — no report (value reads x). `x = 1; if (c) {} x = 2` — no report
  (different blocks). Compound assignments/increments never create a pending entry.

## V3057 — function receives an odd argument (definitely negative)

- PVS: "Function receives an odd argument." V1 scope: arguments that must be non-negative
  but are **always negative** by interval analysis.
- Mechanism: `DataFlowRule<ImmutableDictionary<SsaId, IntervalValue>>` on the interval
  pipeline (ovs-kmj). OnState:
  - `IInvocationOperation` on `string` instance methods `Substring`, `Remove`, `PadLeft`,
    `PadRight`: any `int` argument with `interval.Upper < 0` ⇒ report.
  - `IArrayCreationOperation` whose dimension size interval has `Upper < 0` ⇒ report.
- Definite-only: `Upper < 0` means every possible value is negative; unknown (⊤) stays silent.

## V3120 — potentially infinite loop

- PVS: "The variable from the loop exit condition does not change its value between
  iterations."
- Mechanism: `AstRule` on `while` / `do-while` / `for` syntax. Flag when ALL hold:
  1. The condition references at least one local/parameter, and consists ONLY of
     identifiers, literals, `!`/unary minus, binary operators, parens, casts — any
     invocation, member/element access, `await`, pattern ⇒ skip (state may change).
  2. No condition variable is written in the body (or for-incrementors): no assignment,
     compound assignment, `++`/`--`, no passing as `ref`/`out`, and no lambda / local
     function / anonymous method inside the body that references a condition variable.
  3. The body contains no `break`, `return`, `goto`, `throw`, or `yield break` (loop can
     only exit via the condition).
- Report at the loop condition.

## Out of scope (follow-ups)

- V3008 cross-block dominance-based dead stores; field dead stores.
- V3057 MAY variant, more APIs (collections, `Array.Copy`, spans), upper-bound checks
  (count beyond length).
- V3120 field-based conditions with body invocation purity analysis.
